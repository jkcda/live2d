# 立绘素材规格（PNGTuber 模式）

把自己的角色接进来的**最省事路径**：不需要 Live2D 建模，只要几张差分图。
渲染层见 `src/core/portrait/stage.ts`，加载与校验见 `src/core/portrait/assets.ts`。

---

## 一、最小可用：只要一张图

把任意一张角色立绘命名为 `body.png` 丢进 `public/portrait/`，再写一份 `portrait.json`，
她就「活了」：

- 呼吸：上下浮动 + 轻微缩放
- 头部偏转：左右位移 + 旋转
- 张嘴：**拉伸下巴分界线以下的像素**（靠 `jawLine` 指位置）
- 点她有反应：摸头点头、戳身体弹一下

代价：**不眨眼、嘴型只有「拉下巴」这一种**。适合先看效果，不适合长期用。

---

## 二、完整素材（推荐）

全部放在 `public/portrait/`：

| 文件 | 必需 | 说明 |
|---|---|---|
| `portrait.json` | 可选 | 配置。不写就按底图自动推导（推荐先不写，不满意再覆盖） |
| `body.png` | ✅ | 底图（含脸、身体）。**必须是闭嘴+睁眼那张**，其余状态都以它为基准 |
| `mouth_1.png` | 建议 | 嘴：张开（做一张就够用；张得越明显，说话感越强） |
| `mouth_2.png` | 可选 | 嘴：张更大。**不是必须** —— 张太大反而不好看，宁缺毋滥 |
| `eyes_closed.png` | 建议 | 眼：**闭** |
| `mouth_0.png` | **不用做** | 嘴：闭。底图本身就是闭着嘴，**「闭嘴」= 不叠任何东西**，程序会自动补 |
| `eyes_open.png` | **不用做** | 眼：睁。同理，底图已是睁眼 |
| `hair_front.png` | 可选 | 前发。单独一层，晃动时动得比身体多一点，更生动 |
| `hair_back.png` | 可选 | 后发。画在身体后面，转头时露出来 |

**所以真正要做的只有 2 张**：`mouth_1` + `eyes_closed`。

> 为什么这么设计：差分图是「叠在底图上面的东西」。底图已经是闭嘴+睁眼，
> 那两个状态只需要「什么都不叠」。实测 2 张（闭嘴 / 张开）口型就能正常切换、眨眼正常。
> 档数由你决定：程序从 `mouth_0` 起**连续编号**读，缺号就停，
> 所以 1 张、2 张、3 张都能跑，高振幅时自动用最后一张。
>
> 当前角色用的是 2 档。曾经做过 3 档（第三张取自「全张」那张变体），
> 实际看下来嘴张太大不自然，就删掉了 —— 宁少勿滥。


### 三条硬性约定

1. **所有图尺寸完全一致**，等于 `portrait.json` 里的 `canvas`。
2. **差分图按整张画布尺寸导出**，只有对应区域有内容、其余全透明。
   —— 不要裁成小图再对位，那样一定会偏。
3. PNG，带透明通道。

> 画师交付的 PSD 本来就是「底图 + 眼睛层 + 嘴层」这么分层的，
> 从 PSD 导出这几张几乎是零成本 —— 直接把需求原样转给画师即可。

### 口型是怎么算出来的（为什么一张差分也能连续开合）

映射见 `src/core/portrait/stage.ts` 的 `mouthLevel()`：

1. 开口度 `m` 低于 `0.10` → **第 0 张 = 不叠任何东西 = 闭嘴**；
2. 否则先算一个连续的开度（`0.35 ~ 1`，低开度用幂函数抬一抬 —— 小振幅在听觉上
   也是「在说话」，嘴不能只开一条缝）；
3. 有几张差分就分几档，取「标称开度 ≥ 当前开度」的那一张，
   再把这张图**绕上唇线纵向缩放** `开度 / 该档标称开度`。

这么做有两个理由，都是踩过的坑：

- **只有一张 `mouth_1` 时，光靠换图就只有「闭 / 全开」两态**，
  而说话时振幅几乎不会掉到阈值以下 —— 表现就是「全程张嘴」，
  让人误以为没做闭嘴差分。加了连续缩放之后，小振幅只是微张。
  （实测：开口度 0.15 / 0.35 / 0.6 / 1.0 时，嘴上变化的像素数是 73 / 100 / 134 / 177，单调递增。）
- **换图那一刻两张要连得上**：缩放取 `开度 / 标称开度`，所以从第 1 张换到第 2 张时
  视觉大小是连续的，不会「突然大一圈」。

缩放支点（上唇线中点）不是写死的，而是加载时**量差分图的 alpha 包围盒**得到的
（`assets.ts` 的 `measurePatchBox`）—— 每个人的嘴在哪不一样。

> 顺带一个教训：**测试音必须有真正的静音段**，否则测不出「会不会闭嘴」。
> 最早的测试音是连续音，振幅全程在阈值以上，离线模拟出来 192 帧里只有 3 帧闭嘴、
> 最长连续张嘴 3.15 秒（等于整段），看起来就像口型坏了。
> 现在是「0.22s 出声 + 0.13s 静音，每 4 个音节停 0.4s」：闭嘴帧 14%、开口缩放 0.38~0.93。

## 三、差分图怎么来（三条路）

### 1. 已经有「AI 改过的整张立绘」→ 用脚本自动做（推荐）

```powershell
cd python
# 先只看报告，确认它找到的改动区域是对的
.venv\Scripts\python.exe tools\make_differential.py `
  --base ..\public\portrait\body.png `
  --variant ..\vendor\portrait-ai-output\张嘴半张.png `
  --box 770,390,865,465 --threshold 30 --report-only

# 没问题就加 --out 出图
.venv\Scripts\python.exe tools\make_differential.py `
  --base ..\public\portrait\body.png `
  --variant ..\vendor\portrait-ai-output\张嘴半张.png `
  --box 770,390,865,465 --threshold 30 `
  --out ..\public\portrait\mouth_1.png
```

原理：把底图和 AI 结果**逐像素比**，只把真正变了的连通区域做成差分（边缘羽化）。
于是「框外漂移」自动消失 —— 它压根没被复制过来。

- `--box` 把搜索范围收窄到脸。**不填就会把 AI 在头发/袖口/裙摆上的重画也一起收进来**，
  那种差分图会让角色在说话时全身微闪。
- 报告里 `保留下来的块` 应该是 1~3 个、几百到两千像素。
  如果看到「上百个块散在全身」，说明这次 AI 编辑是整张重画，别用，重做一次。
- 报告里 `丢弃的「框外漂移」` 越小越好。比阈值（默认 30 的一半以上）还大，
  说明这张结果画风已经飘了，贴上去会突兀。
- `--threshold` 调低会收进更多细微改动，调高只留明显改动。嘴/眼这种改动很显著，30 够用。

### 2. 网页版差分工具 `public/dev/diff-tool.html`（手拖框）

给 ComfyUI 那种「只返回改动块」的流程用：拖框 → 导出放大裁剪图 → AI 重绘 → 选回结果自动合成。

> ⚠ 手拖框有两个必然的坑：**拖大了**会把框外 AI 顺手重画的像素一起贴上去
> （脸上一块矩形和周围对不上，这就是「嘴和脸对不上」的来历）；
> **拖偏了**会让嘴缺一块。所以只要能拿到「AI 改过的整张图」，优先用上面第 1 条。

### 3. 画师 PSD 分层导出（最准）

底图 + 眼睛层 + 嘴层，导出成本几乎为零，直接按上面的规格交付。

### 当前底的实测坐标（1600×2848，换底图后作废）

| 部位 | 像素范围 | 比例（x, y, w, h） |
|---|---|---|
| 嘴 | x 787–844, y 402–455 | 0.4813, 0.1412, 0.0594, 0.0221 |
| 眼（左右一起） | x 712–921, y 259–365 | 0.4450, 0.0909, 0.1306, 0.0372 |

这两组数是「底图 vs 变体」逐像素比出来的改动范围（`make_differential.py` 的 `--box`
就该取它们的略微外扩值），也是往网页版差分工具里拖框时的参考。
现用的两张差分来自：`mouth_1` ← 变体「半张」，`eyes_closed` ← 变体「闭眼」
（变体原图存在 `vendor/portrait-ai-output/`，不入库）。

## 四、`portrait.json` 说明

```jsonc
{
  "name": "我的角色",
  "canvas": { "width": 800, "height": 1100 },   // 所有差分图的尺寸

  // 缩放基准：画布里哪一块算「角色」（比例 0~1）。
  // 布局时按这块的高度铺满窗口。留白多的时候一定要填，否则角色会很小。
  "content": { "x": 0.13, "y": 0.06, "width": 0.74, "height": 0.92 },

  // 下巴分界线（0~1，相对画布高度）：没有嘴差分时靠拉伸它以下的部分表现张嘴
  "jawLine": 0.5,

  // 命中区（比例 0~1）：决定点击反应。名字用 Head / Body 以对齐 Live2D 那套
  "regions": {
    "Head": { "x": 0.26, "y": 0.06, "width": 0.48, "height": 0.36 },
    "Body": { "x": 0.14, "y": 0.42, "width": 0.72, "height": 0.56 }
  },

  // 待机幅度，嫌动得太厉害就调小
  "motion": { "bobPercent": 0.012, "swayDegrees": 2.2, "breatheScale": 0.006 }
}
```

参考现成的一份：`public/portrait/_placeholder/portrait.json`（占位角色，可直接对照改）。
自己用的时候**建议先不写** —— 不写就按底图自动推导取景/命中区，实测够用；
只有推导出来的取景不满意（比如头顶留白太多）才需要写一份覆盖。

## 五、怎么看效果 / 怎么排查

| 做法 | 用途 |
|---|---|
| `http://localhost:5176/?portrait=1` | 临时切到立绘模式（不改设置） |
| `http://localhost:5176/?live2d=1` | 临时切回 Live2D |
| 设置 → 角色 → 渲染方式 | 正式切换（会刷新页面） |
| 控制台 `__nexusPortrait.counts` | 看每类素材加载到了几张：`{mouths, hasEyes, hasHairFront, hasHairBack}` |
| 控制台 `__nexusPortrait.shown` | 看当前显示的嘴型索引 / 眼睛开合 / 嘴的纵向缩放 |
| `node tools/verify-portrait.mjs` | **自动验证**（见下） |

**素材没生效时先看 `counts`**：比如 `mouths: 0` 就说明嘴差分名不对（必须是 `mouth_0.png` 起、
从 0 连续编号，缺号会从那里断掉），或 `portrait.json` 的 `canvas` 尺寸和图片不一致。

### 自动验证：不用靠肉眼

```powershell
node tools/verify-portrait.mjs        # dev server 要在 5176 上跑着
```

它会真的开一个窗口把应用跑起来，然后：

1. 报素材状态（`counts`、取景、命中率、当前嘴型）；
2. **冻住待机动画**（必须冻 —— 否则呼吸/摆动让整张画面都在变，逐像素比等于什么都没测），
   分别把口型设成 0 / 0.3 / 0.9、眼睛设成睁/闭各截一张；
3. 再走一遍**口型渐变**（0 / 0.15 / 0.35 / 0.6 / 1.0）各截一张，并打印每一档的
   差分序号与纵向缩放；
4. 把截图存在系统临时目录并打印路径，供逐像素比较。

怎么判读比较结果：

| 现象 | 说明 |
|---|---|
| 三张截图完全一样 | 差分没生效：文件名不对 / 尺寸和底图不一致 / 没放进 `public/portrait/` |
| 只有脸上一小块在变（几百像素） | 正常。嘴在眼的**正下方、左右居中**就说明对位正确 |
| 全身大面积在变 | 差分图里混进了 AI 的整张漂移，要按第三节重做 |
| 渐变的 5 张里变化像素数**不递增** | `mouthLevel()` 的映射坏了（表现就是「只会全开」） |

## 六、这个方案的边界

诚实说明它能做到什么、做不到什么：

| 能做到 | 做不到 |
|---|---|
| 张嘴说话（1~3 档嘴型，看你做了几张差分）、随机眨眼 | 立体转头（侧脸、仰头） |
| 呼吸浮动、身体微摆 | 发丝物理、衣服摆动 |
| 摸头/戳身体的即时反应 | 复杂动作（她自带的动作组） |
| 任意画风、任意比例 | 表情的细腻变化（只能靠换整张差分） |

要上面那些「做不到」的，才需要走 Live2D 建模（Cubism Editor 自己做，或委托建模师）。
两者的交互层是同一套代码，所以将来升级到 Live2D，界面和手感不用重做。
