# 立绘素材规格（PNGTuber 模式）

把自己的角色接进来的**最省事路径**：不需要 Live2D 建模，只要几张差分图。
渲染层见 `src/core/portrait/stage.ts`，加载与校验见 `src/core/portrait/assets.ts`。

---

## 一、最小可用：只要一张图

把任意一张角色立绘命名为 `body.png` 丢进 `public/portrait/`，再写一份 `portrait.json`，
她就「活了」：

- 呼吸：上下浮动 + 轻微缩放
- 头部偏转：左右位移 + 旋转
- 张嘴：**拉伸下巴分界线以下的像素**（靠 `jawLine` 指位置）
- 点她有反应：摸头点头、戳身体弹一下

代价：**不眨眼、嘴型只有「拉下巴」这一种**。适合先看效果，不适合长期用。

## 二、完整素材（推荐）

全部放在 `public/portrait/`：

| 文件 | 必需 | 说明 |
|---|---|---|
| `portrait.json` | 可选 | 配置。不写就按底图自动推导（推荐先不写，不满意再覆盖） |
| `body.png` | ✅ | 底图（含脸、身体）。**必须是闭嘴+睁眼那张**，其余状态都以它为基准 |
| `mouth_1.png` | 建议 | 嘴：张开（做一张就够用；张得越明显，说话感越强） |
| `mouth_2.png` | 可选 | 嘴：张更大。**不是必须** —— 张太大反而不好看，宁缺毋滥 |
| `eyes_closed.png` | 建议 | 眼：**闭** |
| `pupil.png` | 可选 | **瞳孔/虹膜图层**（抠出来的）。有了它眼睛才能真正跟着鼠标动，见下面「瞳孔图层怎么做」 |
| `expr_<id>.png` | 可选 | **表情差分**（整张脸的表情）。id 见下表，一张一个情绪，见下面「表情差分怎么做」 |
| `pose_<id>.png` | 可选 | **姿态差分**（招手之类）。整身替换图，不是叠上去的差分；`pose_<id>_b.png` 是第二帧（有就真的挥起来），见「姿态差分怎么做」 || `mouth_0.png` | **不用做** | 嘴：闭。底图本身就是闭着嘴，**「闭嘴」= 不叠任何东西**，程序会自动补 |
| `eyes_open.png` | **不用做** | 眼：睁。同理，底图已是睁眼 |
| `hair_front.png` | 可选 | 前发。单独一层，晃动时动得比身体多一点，更生动 |
| `hair_back.png` | 可选 | 后发。画在身体后面，转头时露出来 |

**所以真正要做的只有 2 张**：`mouth_1` + `eyes_closed`。

> 为什么这么设计：差分图是「叠在底图上面的东西」。底图已经是闭嘴+睁眼，
> 那两个状态只需要「什么都不叠」。实测 2 张（闭嘴 / 张开）口型就能正常切换、眨眼正常。
> 档数由你决定：程序从 `mouth_0` 起**连续编号**读，缺号就停，
> 所以 1 张、2 张、3 张都能跑，高振幅时自动用最后一张。
>
> 当前角色用的是 2 档。曾经做过 3 档（第三张取自「全张」那张变体），
> 实际看下来嘴张太大不自然，就删掉了 —— 宁少勿滥。


### 三条硬性约定

1. **所有图尺寸完全一致**，等于 `portrait.json` 里的 `canvas`。
2. **差分图按整张画布尺寸导出**，只有对应区域有内容、其余全透明。
   —— 不要裁成小图再对位，那样一定会偏。
3. PNG，带透明通道。

> 画师交付的 PSD 本来就是「底图 + 眼睛层 + 嘴层」这么分层的，
> 从 PSD 导出这几张几乎是零成本 —— 直接把需求原样转给画师即可。

### 口型是怎么算出来的（为什么一张差分也能连续开合）

映射见 `src/core/portrait/stage.ts` 的 `mouthLevel()`：

1. 开口度 `m` 低于 `0.10` → **第 0 张 = 不叠任何东西 = 闭嘴**；
2. 否则先算一个连续的开度（`0.35 ~ 1`，低开度用幂函数抬一抬 —— 小振幅在听觉上
   也是「在说话」，嘴不能只开一条缝）；
3. 有几张差分就分几档，取「标称开度 ≥ 当前开度」的那一张，
   再把这张图**绕上唇线纵向缩放** `开度 / 该档标称开度`。

这么做有两个理由，都是踩过的坑：

- **只有一张 `mouth_1` 时，光靠换图就只有「闭 / 全开」两态**，
  而说话时振幅几乎不会掉到阈值以下 —— 表现就是「全程张嘴」，
  让人误以为没做闭嘴差分。加了连续缩放之后，小振幅只是微张。
  （实测：开口度 0.15 / 0.35 / 0.6 / 1.0 时，嘴上变化的像素数是 77 / 107 / 141 / 177，单调递增。）
- **换图那一刻两张要连得上**：缩放取 `开度 / 标称开度`，所以从第 1 张换到第 2 张时
  视觉大小是连续的，不会「突然大一圈」。

> ★ **差分是叠在底图上的，所以缩放支点必须选对。**
> 支点不是写死的，而是加载时量差分图 alpha 的**质心**得到的（`assets.ts` 的 `measurePatchBox`）——
> 质心大致就是嘴的中线。曾经按「区间上边缘」当支点，一压扁整块往上缩，
> 底图那条闭嘴线就从下面露出来，看起来像「底图的闭嘴一直在」。
> 绕质心则两头都稳：嘴不跑位，闭嘴线一直被盖住。
> 另外**横向不要缩放** —— 嘴一收窄，底图闭嘴线的两端就露出来了。
>
> 这条也解释了排查时该量什么：不看截图好不好看，而是看
> **「闭嘴线所在的那一行有没有出现在两次截图的差异里」**。

> 顺带一个教训：**测试音必须有真正的静音段**，否则测不出「会不会闭嘴」。
> 最早的测试音是连续音，振幅全程在阈值以上，离线模拟出来 192 帧里只有 3 帧闭嘴、
> 最长连续张嘴 3.15 秒（等于整段），看起来就像口型坏了。
> 现在是「0.22s 出声 + 0.13s 静音，每 4 个音节停 0.4s」：闭嘴帧 14%、开口缩放 0.38~0.93。

### 待机为什么会「一直在漂浮」

两个原因，都修过了，记在这里免得改回去：

1. **旋转/缩放的支点**。root 容器不设 `pivot` 时，Pixi 是绕**画布左上角 (0,0)** 做旋转的，
   而角色中心离那个角有 1600 多像素 —— 于是「微摆 ±2.8°」变成半径 1600 的圆弧，
   整个人横向漂 ±80 像素、纵向跟着画圈。现在支点设成**角色底部中点**（腰或脚）：
   下半身钉住、上半身轻微晃，这才是待机该有的样子。
2. **幅度**。呼吸浮动（`bobPercent`）和摆动（`swayDegrees`）原来给到 1.2% / 2.2°，
   收回成 0.4% / 0.8° —— 待机是**永远在跑**的底色，稍微大一点就像在飘。

实测（脚本连拍 8 张，量轮廓上下沿漂了多少像素）：

| 待机幅度 | 轮廓上沿 | 轮廓下沿 |
|---|---|---|
| 标准 | 16 px（就是呼吸） | **0 px（钉死）** |
| 静止 | 0 px | 0 px |

嫌飘或嫌静都不用改代码：**设置 → 角色 → 待机动作**（标准 / 轻微 / 静止）立刻生效，
眨眼不受影响。要按角色单独调，写进 `portrait.json` 的 `motion` 覆盖即可。

## 三、差分图怎么来（三条路）

### 1. 已经有「AI 改过的整张立绘」→ 用脚本自动做（推荐）

```powershell
cd python
# 先只看报告，确认它找到的改动区域是对的
.venv\Scripts\python.exe tools\make_differential.py `
  --base ..\public\portrait\body.png `
  --variant ..\vendor\portrait-ai-output\张嘴半张.png `
  --box 770,390,865,465 --threshold 30 --report-only

# 没问题就加 --out 出图
.venv\Scripts\python.exe tools\make_differential.py `
  --base ..\public\portrait\body.png `
  --variant ..\vendor\portrait-ai-output\张嘴半张.png `
  --box 770,390,865,465 --threshold 30 `
  --out ..\public\portrait\mouth_1.png
```

原理：把底图和 AI 结果**逐像素比**，只把真正变了的连通区域做成差分（边缘羽化）。
于是「框外漂移」自动消失 —— 它压根没被复制过来。

- `--box` 把搜索范围收窄到脸。**不填就会把 AI 在头发/袖口/裙摆上的重画也一起收进来**，
  那种差分图会让角色在说话时全身微闪。
- 报告里 `保留下来的块` 应该是 1~3 个、几百到两千像素。
  如果看到「上百个块散在全身」，说明这次 AI 编辑是整张重画，别用，重做一次。
- 报告里 `丢弃的「框外漂移」` 越小越好。比阈值（默认 30 的一半以上）还大，
  说明这张结果画风已经飘了，贴上去会突兀。
- `--threshold` 调低会收进更多细微改动，调高只留明显改动。嘴/眼这种改动很显著，30 够用。

### 2. 网页版差分工具 `public/dev/diff-tool.html`（手拖框）

给 ComfyUI 那种「只返回改动块」的流程用：拖框 → 导出放大裁剪图 → AI 重绘 → 选回结果自动合成。

> ⚠ 手拖框有两个必然的坑：**拖大了**会把框外 AI 顺手重画的像素一起贴上去
> （脸上一块矩形和周围对不上，这就是「嘴和脸对不上」的来历）；
> **拖偏了**会让嘴缺一块。所以只要能拿到「AI 改过的整张图」，优先用上面第 1 条。

### 3. 画师 PSD 分层导出（最准）

底图 + 眼睛层 + 嘴层，导出成本几乎为零，直接按上面的规格交付。

### 当前底的实测坐标（1600×2848，换底图后作废）

| 部位 | 像素范围 | 比例（x, y, w, h） |
|---|---|---|
| 嘴 | x 787–844, y 402–455 | 0.4813, 0.1412, 0.0594, 0.0221 |
| 眼（左右一起） | x 712–921, y 259–365 | 0.4450, 0.0909, 0.1306, 0.0372 |

这两组数是「底图 vs 变体」逐像素比出来的改动范围（`make_differential.py` 的 `--box`
就该取它们的略微外扩值），也是往网页版差分工具里拖框时的参考。
现用的两张差分来自：`mouth_1` ← 变体「半张」，`eyes_closed` ← 变体「闭眼」
（变体原图存在 `vendor/portrait-ai-output/`，不入库）。

## 四、`portrait.json` 说明

```jsonc
{
  "name": "我的角色",
  "canvas": { "width": 800, "height": 1100 },   // 所有差分图的尺寸

  // 缩放基准：画布里哪一块算「角色」（比例 0~1）。
  // 布局时按这块的高度铺满窗口。留白多的时候一定要填，否则角色会很小。
  "content": { "x": 0.13, "y": 0.06, "width": 0.74, "height": 0.92 },

  // 下巴分界线（0~1，相对画布高度）：没有嘴差分时靠拉伸它以下的部分表现张嘴
  "jawLine": 0.5,

  // 命中区（比例 0~1）：决定点击反应。名字用 Head / Body 以对齐 Live2D 那套
  "regions": {
    "Head": { "x": 0.26, "y": 0.06, "width": 0.48, "height": 0.36 },
    "Body": { "x": 0.14, "y": 0.42, "width": 0.72, "height": 0.56 }
  },

  // 待机幅度，嫌动得太厉害就调小
  "motion": { "bobPercent": 0.012, "swayDegrees": 2.2, "breatheScale": 0.006 }
}
```

参考现成的一份：`public/portrait/_placeholder/portrait.json`（占位角色，可直接对照改）。
自己用的时候**建议先不写** —— 不写就按底图自动推导取景/命中区，实测够用；
只有推导出来的取景不满意（比如头顶留白太多）才需要写一份覆盖。

### 瞳孔图层怎么做（让眼睛真的跟着动）

```powershell
cd python
.venv\Scripts\python.exe tools\extract_pupils.py            # 抠 + 补眼白 + 出预览
.venv\Scripts\python.exe tools\extract_pupils.py --dry-run  # 只看报告
```

一条命令做三件事：抠出 `pupil.png`、把底图的瞳孔位置**补成眼白**、出一张放大对比图
（左 原图 / 中 补完 / 右 图层）供肉眼验收。原底图备份在
`vendor/portrait-base-with-pupil/body.png`，要还原直接复制回去。

原理与坑（都是量出来的，不是推测）：

- 瞳孔和虹膜是**同一块带饱和度的团**（实测瞳孔暗核饱和度 0.58，远高于眼白），
  按"饱和度 + 暗度"能整块分离；外面的睫毛线饱和度低，正好被排除。
  再取连通块 ∩ **内接椭圆**，把睫毛/眉毛切干净（否则一移动就是"睫毛在漂"）。
- 补洞用**从洞边向内传播**，而不是"用周围平均色填一层"：眼周有明暗过渡
  （上眼睑阴影、外眼角偏暗），纯色填上去像贴了块胶布。
- 位移上限被素材限死：虹膜左右各约 14px 眼白、上下约 8px，所以
  `PUPIL_SHIFT_MAX_PX = 10`、纵向再乘 0.55。越过就把补出来的眼白推出眼睛轮廓。
- **闭眼时瞳孔要回中位**（代码里乘了 eyeOpen）：差分只覆盖原位置的虹膜，
  移出去那部分盖不住，不回去的话眨眼瞬间会有一小块眼珠露在闭眼图外面。

自检（脚本会打印，不通过就别用）：

| 检查 | 实测 | 含义 |
|---|---|---|
| 图层叠回补好的底图 vs 原图 | 平均差 1.12 / 最大 100（只在羽化边） | 无损还原，画质没丢 |
| 补完的洞里最暗亮度 | 0.04 → **0.59**，残留暗像素 0 | 瞳孔确实抠走了、没留黑点 |



指针 → 视角的计算在 `core/character/gaze.ts`，**渲染器无关**；怎么表现由各自决定：

| 渲染器 | 怎么表现"看" | 素材要求 |
|---|---|---|
| Live2D | 瞳孔写 `ParamEyeBallX/Y`（满幅）+ 头转 ±7° | 无（模型自带） |
| 立绘 | **只动瞳仁**：瞳孔图层平移 ±3 画布像素（身体刻意完全不动，见下） | `pupil.png` |

> ★ 立绘的身体视差（整体平移 0.7% + 绕腰倾斜 1.6°）现在**全部置 0**，是用户比过两种之后选的：
> 整体平移读成"整个人在滑"，绕腰倾斜又太像待机摇晃，他要的是"眼睛跟着你动"——
> 所以画面里唯一响应鼠标的就是瞳仁。想恢复整体视差，把 `stage.ts` 里
> `GAZE_SHIFT_RATIO / GAZE_LIFT_RATIO / GAZE_ROLL_DEG` 调回 `0.007 / 0.003 / 1.6` 即可。
>
> 代价要说清楚：瞳仁的余量只有 3~4 画布像素（素材决定的，见 `PUPIL_SHIFT_MAX_PX`），
> 换算到 420×640 的桌宠窗口不到 1 个屏幕像素 —— 视线跟随现在是**很轻**的效果。
> 想要更明显，只有两条路：把虹膜抠得小一点（余量大），或者恢复整体视差。

立绘没有独立瞳孔图层时（`features.gaze` 显示为「缺：瞳孔跟随」），"看"就完全靠整体位移 ——
那是 PNGTuber 的通行做法，观感比想象中强：人对"她朝我这边转过来了"很敏感。
幅度是**按角色高度的比例**算的，所以浏览器全屏和桌宠小窗看起来一致（`GAZE_SHIFT_RATIO`）。

两个实现上的坑，都写进注释了：
- **基准点必须是渲染器给的**（`CharacterStage.anchor('head')`），不能用窗口中心 ——
  取景是"底部居中 + 等比缩放"，脸的位置随窗口比例变，用窗口中心算会"看着鼠标但视线偏一边"；
- 锚点要用**静止时**的位置算（stage 里缓存 restX/restY），拿当前帧的位置会形成负反馈：
  她朝鼠标挪 → 相对角度变小 → 挪得更少，表现为"幅度比预期小、还发黏"。



同一个角色如果待机太飘、或者立绘振幅偏小导致嘴张不开，不用改代码，也不用改
`portrait.json`（那个是**素材**的属性），在角色清单里按角色覆盖：

```jsonc
{
  "id": "me", "name": "我的角色", "kind": "portrait", "dir": "portrait",
  "tuning": {
    "idleFactor": 0.5,                                   // 待机幅度倍率（覆盖设置里的全局档位）
    "motion": { "bobPercent": 0.004, "swayDegrees": 0.8, "breatheScale": 0.004 },
    "mouth":  { "closedLevel": 0.1, "minOpenScale": 0.35 },  // 嘴：更容易闭 / 微张更明显
    "lipsync": { "gain": 1.6, "attackMs": 45, "releaseMs": 110 }  // 口型手感
  }
}
```

优先级：`tuning` > `portrait.json` 的 `motion` > 内置默认。
清单里还能放多个角色（甚至同一个角色的两套素材并存），设置 → 角色 里切换，**不用刷新页面**。

## 五、表情差分怎么做（`expr_<id>.png`）

一张表情 = 一张**整张画布的差分图**（和画师 PSD 里的"表情层"一致），文件名声明情绪：

| 文件名 | 界面名 | 情绪 | 也用别名 |
|---|---|---|---|
| `expr_happy.png` | 开心 | happy | `expr_高兴.png` / `expr_笑.png` |
| `expr_shy.png` | 害羞 | shy | `expr_羞.png` |
| `expr_surprised.png` | 惊讶 | surprised | `expr_吃惊.png` |
| `expr_angry.png` | 生气 | unhappy | `expr_愤怒.png` / `expr_怒.png` |
| `expr_sad.png` | 伤心 | unhappy | `expr_难过.png` / `expr_悲伤.png` |
| `expr_neutral.png` | 无语 | neutral | `expr_平静.png` |

清单在 `src/core/portrait/expressions.ts`，**素材探测**（设置面板）和**加载**用的是同一份 ——
所以"能力里显示有表情"和"点了真的有反应"不会打架。放了别的名字不会生效，
但控制台会打印实际加载到哪几张：

```
[portrait] 表情差分 2 张：angry(生气)、sad(伤心)
```

表情层**没有**的就自动没有：一张都没有时，`features.expressions` 为 false，
悬浮条上不出现表情按钮，戳她也只是弹一下 —— 不会"点了没反应"。

### 图层顺序（往上一格就丢东西）

```
后发 → 底图 → 表情 → 瞳孔 → 眼差分 → 【遮嘴块】 → 口型差分 → 前发
```

- 在**底图之上**：表情才能盖住底图原本的眉毛（不然"皱眉"只皱一半）；
- 在**瞳孔之下**：瞳仁还看得见，"眼睛跟着鼠标动"不会被表情吃掉；
- 在**眼差分之下**：眨眼还能盖住它（表情画的是睁着眼睛的脸）。

### 说话时表情的嘴要"让位"

表情差分里也画了一张嘴，而口型是**另一条图层**（`mouth_1.png` 缩放叠加）——
两张嘴会在同一张脸上。所以：

- 闭嘴那一档（口型差分是**空纹理**）→ 露出表情自己的嘴；
- 真的在叠口型差分时 → 用一块**底图同位置的切片**把表情的嘴盖上，
  于是说话时看到的和"没有表情功能"时完全一样。

判据用的是**口型那一档的索引**（`pick.index > 0`）而不是开口度阈值：
阈值和 `mouthLevel()` 里的 `closedLevel` 是两套数，改一个忘另一个就会
"嘴闭着却盖着表情的嘴"。

> 遮嘴块是**借底图同一份 GPU 纹理**切出来的子矩形，不额外占显存
> （给每张表情"挖个洞"要多存一张整画布纹理，1600×2848×4 ≈ 18MB/张）。
> 代价是那个矩形里凡是表情画的东西都会被底图盖掉，所以它必须只框住嘴：
> `MOUTH_COVER_MARGIN = 6` 是实测出来的（嘴差分包围盒往外扩 6px 恰好只包住嘴，
> 扩到 8px 就开始切到脸颊的 7 个像素，说话时会闪一下）。**换素材要重测这个值。**

### 怎么触发

| 方式 | 行为 |
|---|---|
| 戳身体 | 按情绪挑一张（"戳一下她不满"）：有 `surprised` 优先，否则 `unhappy`，**4 秒后自动收回** |
| 摸头 | 优先 `happy` / `shy` / `neutral` |
| 悬浮条上的按钮 | 手动切，**不过期**（用户是特意选的）；再点一下收回素颜 |
| `__nexusPortrait.setExpression('sad')` | 控制台手动切 |

情绪编排和 Live2D **共用一套**（`core/live2d/reactions.ts` 的 `pickExpression`），
区别只在情绪从哪来：Live2D 从 exp3 驱动的参数**推**，立绘推不出来，只能由文件名声明。

> ★ 立绘走 **strict** 模式：没有对得上情绪的表情时**宁可不变脸**。
> Live2D 是"宁可重复也别没反应"（模型的表情是一整套，总能挑到一个），
> 而立绘的表情是画师一张张画的 —— 只有「生气」「伤心」两张素材时，
> 摸头随机甩一张生气的脸，比没有反应更糟。

### 素材怎么来

和嘴/眼差分同一条路：让 AI 改一张脸，再用 `make_differential.py` 抠出改动区域。

```powershell
# 先只看报告：确认它找到的改动区域就是"表情"，没有把整张脸的漂移也算进去
python python/tools/make_differential.py vendor/portrait-ai-output/愤怒.png `
  --base public/portrait/body.png --box 680,230,960,470 --threshold 30 --report-only

# 报告没问题再出图
python python/tools/make_differential.py vendor/portrait-ai-output/愤怒.png `
  --base public/portrait/body.png --box 680,230,960,470 --threshold 30 `
  --out public/portrait/expr_angry.png
```

`--box` 要**框住眉眼和嘴、避开画面边缘**：AI 改图时常常整张画布平移一两个像素，
不框住的话边缘会浮出一圈"漂移差分"，叠上去就是一圈毛边（实测删掉过两块这种）。

## 六、姿态差分怎么做（`pose_<id>.png`）

**表情和姿态是两件事**，素材做法完全不同，别混：

| | 表情 `expr_<id>.png` | 姿态 `pose_<id>.png` |
|---|---|---|
| 改什么 | 脸（眉毛/眼睛/嘴） | 整个人（抬手、弯腰、叉腰） |
| 素材形态 | **叠上去的差分**：只有改动区域有内容，其余透明 | **整身替换图**：整张抠好底的立绘 |
| 为什么 | 叠上去就能盖住原来的五官 | "把原来的手放下来"没法靠叠一层表达 —— 图层只能加像素、不能擦像素，垂着的那条胳膊会留在原地，看起来她有两只手 |
| 切换方式 | 直接显示/隐藏图层 | 和底图**交叉淡入淡出**（170ms） |
| 一张能做几个 | 一个情绪 | 一个姿势 |

### 素材怎么做

让 AI 改一张（比如"把左手抬起来挥手"），然后**一个脚本搞定**：

```powershell
cd python
.venv/Scripts/python tools/make_pose.py ../vendor/portrait-ai-output/招手.png `
    --base ../public/portrait/body.png --out ../public/portrait/pose_wave.png
```

它做两件事，第二件是关键：

1. **抠底**（isnet-anime，和 `cutout.py` 同一个模型）；
2. **把头部区域恢复成底图那张** —— AI 改图时会顺手把整张脸也重画一遍
   （实测招手图里瞳孔、发丝边缘、脸颊阴影一共约 1.8 万像素和底图不一致），
   直接换上去她一招手脸就轻微变样，很出戏。所以头部框（默认 `x≥640, y<520`）里
   凡是底图有像素的地方一律用底图。

自检会把结果打出来，**头部区域改了 0 个像素才算过**（不为 0 时退出码 1，别直接用）：

```
脸部还原：头部框 640,0 ~ 1600,520 内改了 145209 个像素（用底图覆盖回去）
自检：
  · 头部框内仍然和底图不同的像素：0  ← 必须是 0
  · 身体部分明显变化（>30）：52777 px  ← 这就是姿态本身
  · 头部框内新出现的像素：2041（AI 把发丝画宽了一点，可忽略）
  · 消失的像素：38859（原来垂着的手臂，正是要它消失的）
```

> 头部框是个矩形，这是有意的：它要"框住整个头、又不压到抬起来的手臂"。
> 换素材（头身比不同、或者手抬得更高）要重调 `--head-box`，
> 自检报错时就是调它的信号。

### 图层顺序与触发

```
后发 → 底图 → 【姿态】 → 表情 → 瞳孔 → 眼差分 → 遮嘴块 → 口型 → 前发
```

姿态在底图之上、脸的图层之下 —— 换姿势时和底图交叉淡入淡出，
而头部区域两边**逐像素一致**，所以淡入淡出期间动的只有身体和手臂，脸和头发一个像素都不动。
（验证脚本会在渲染结果上再验一遍这条：变化必须全在头部框以外。）

| 触发 | 行为 |
|---|---|
| **她登场时**（应用启动、切换角色） | 自动招手一次，3.2 秒后自己收回（`stage.greet()`） |
| **你切回来时** | 离开超过 45 秒再回到窗口，招手打招呼（`AWAY_BEFORE_GREET_MS`，见下） |
| 悬浮条上的「招手」按钮 | 手动摆姿势（一直保持），再点一下回到原姿势 |
| `__nexusPortrait.setPose('wave')` | 控制台手动切；`setPose('wave', 3000)` = 限时 |

「你切回来」听的是两个信号，缺一个都收不全：窗口失焦/获得焦点（`blur`/`focus`，
你 alt-tab 去别处又回来）和窗口被隐藏/显示（`visibilitychange`，最小化、切虚拟桌面）。
桌宠窗口通常一直可见，所以只靠后者收不到信号。

阈值（45 秒）是这条里唯一有产品味道的地方：切窗口一天几百次，每次都招手就成了抽风。
`CharacterStage.vue` 里的 `AWAY_BEFORE_GREET_MS` 一个数，嫌灵敏就调大。

### 第二帧：从「举着手」到「真的在挥手」

一张图只能举着手站着。**两张按节拍交替播放，看起来才是真的在挥手** ——
这是 PNGTuber 的老办法：不做形变，靠离散换图 + 人眼补帧。

命名：第一帧 `pose_wave.png`，第二帧 `pose_wave_b.png`（同一个姿势的第二帧）。
有第二帧就每 300ms 换一次图（`POSE_SWING_MS`），没有就保持不动 —— **不报错，只是动不起来**。

第二帧怎么来：让 AI **在同一张底图上**把抬起的手改到另一个角度
（提示词里强调"只改手臂，脸和头发不要动"），然后跑这条命令 ——
**注意多一个 `--head-from`**（见下）：

```powershell
cd python
.venv/Scripts/python tools/make_pose.py ../vendor/portrait-ai-output/招手2.png `
    --base ../public/portrait/body.png `
    --head-from ../public/portrait/pose_wave.png `
    --out ../public/portrait/pose_wave_b.png
```

`--head-from` 是**做第二帧必须加的**：它把头部区域直接取自第一帧。

为什么需要它：单靠"脸部还原"（用底图覆盖回去）只能保证**底图有像素的地方**一致，
而 AI 每次都会把发丝边缘画宽一点点（第一帧多 2041 px、第二帧多 1282 px）——
两帧一比就差了 896 个像素，全都在发丝边上。300ms 换一次图，那圈发丝就会**闪**。
加上 `--head-from` 之后两帧的头部区域**连 alpha 都逐像素相同**，自检里会多打一行确认：

```
· 与 --head-from（pose_wave.png）在头部框内的差异：0  ← 必须是 0
```

实测两帧的差别（这套素材）：

| 指标 | 数值 |
|---|---|
| 挥手时角色身上可见的变化 | 160046 px（占角色 **15.3%**，肉眼非常大） |
| 两帧手尖位置差 | 横向 208 / 纵向 161 画布像素 ≈ **73 个屏幕像素**（桌宠窗口那一档） |
| 头部框内的差异 | **0**（脸和头发一个像素都不动，连发丝边都不闪） |
| 各自与原姿势相比 | 消失的旧手臂 38859 / 38066 px，新抬起的胳膊 72661 / 69021 px |

> 一条排查经验：这段链路我先用**临时的第二帧**（把头部以下横移 14px）验通过 ——
> `poseFrame` 采样到 `10011001`（在换图）、删掉第二帧后恒为 `00000000`（保持不动）。
> 也就是说"素材没到位"和"代码没写"这两件事从一开始就是分开的。

> 已知退化：没有嘴差分、靠拉下巴张嘴的角色，摆姿势时下巴拉伸会被姿态图盖住
> （和表情的遮嘴块同一个道理，都是"没有嘴素材"那条路线的代价）。

## 七、怎么看效果 / 怎么排查

| 做法 | 用途 |
|---|---|
| `http://localhost:5176/?portrait=1` | 临时切到立绘模式（不改设置） |
| `http://localhost:5176/?live2d=1` | 临时切回 Live2D |
| 设置 → 角色 | 正式切换角色（**不用刷新页面**，正在说话也不会被打断） |
| 控制台 `__nexusPortrait.counts` | 看每类素材加载到了几张：`{mouths, hasEyes, hasPupil, expressions, poses, hasHairFront, hasHairBack}` |
| 控制台 `__nexusPortrait.shown` | 看当前显示的嘴型索引 / 眼睛开合 / 嘴的纵向缩放 / 当前表情 / 当前姿势与混合进度 |
| 控制台 `__nexusPortrait.layers()` | 图层的**真实**可见性（从 Pixi 场景读，不是状态变量） |
| 控制台 `__nexusPortrait.setExpression('sad')` | 手动切一张脸看看（`null` = 素颜） |
| 控制台 `__nexusPortrait.setPose('wave', 3000)` | 手动摆个姿势（第二个参数是限时毫秒，不填就一直保持） |
| 悬浮条上的「招手 / 生气 / 伤心」按钮 | 鼠标移到她身上就浮出来，点一下切、再点收回 |
| `node tools/verify-portrait.mjs` | **自动验证**（见下） |

**素材没生效时先看 `counts`**：比如 `mouths: 0` 就说明嘴差分名不对（必须是 `mouth_0.png` 起、
从 0 连续编号，缺号会从那里断掉），或 `portrait.json` 的 `canvas` 尺寸和图片不一致。

### 自动验证：不用靠肉眼

```powershell
node tools/verify-portrait.mjs        # dev server 要在 5176 上跑着
node tools/verify-portrait.mjs --url "http://localhost:5176/?live2d=1"   # 换 Live2D 也能测待机
```

它会真的开一个窗口把应用跑起来，然后：

1. 报素材状态（`counts`、取景、命中率、当前嘴型）；
2. **冻住待机动画**（必须冻 —— 否则呼吸/摆动让整张画面都在变，逐像素比等于什么都没测），
   分别把口型设成 0 / 0.3 / 0.9、眼睛设成睁/闭各截一张；
3. 再走一遍**口型渐变**（0 / 0.15 / 0.35 / 0.6 / 1.0）各截一张，并打印每一档的
   差分序号与纵向缩放；
4. **表情**：每张差分都在「闭嘴 / 说话」两个状态下各截一张，并断言三件事 ——
   差分真的画上去了（读 Pixi 场景的可见性）、闭嘴时表情自己的嘴露着、说话时它让位给口型；
   再验点击反应（戳身体要变脸、摸头在没有开心素材时**不变脸**）和 4 秒自动收回；
5. **姿态**：摆上/收回各截一张，断言姿态图真的画上去、底图 alpha 淡到 0（没有两张身体叠着）、
   收回后完全恢复；再验 `greet()`（打招呼）几秒后自己收回、帧交替（两帧要换图 / 单帧不许假装在动）、
   以及「切回来时打招呼」的**两侧**（离开 5 秒不打扰、离开 60 秒要招手）。
   截图上还会逐像素比一次：**变化必须全在头部框以外**（脸和头发一个像素都不能动）；
6. 把截图存在系统临时目录并打印路径，供逐像素比较；
7. 连拍两组待机（标准 / 静止）—— 量轮廓上下沿漂了多少像素，用来抓「一直在漂浮」；
8. 最后测**热插拔**（切角色不刷新页面）。

怎么判读比较结果：

| 现象 | 说明 |
|---|---|
| 三张截图完全一样 | 差分没生效：文件名不对 / 尺寸和底图不一致 / 没放进 `public/portrait/` |
| 只有脸上一小块在变（几百像素） | 正常。嘴在眼的**正下方、左右居中**就说明对位正确 |
| 全身大面积在变 | 差分图里混进了 AI 的整张漂移，要按第三节重做 |
| 渐变的 5 张里变化像素数**不递增** | `mouthLevel()` 的映射坏了（表现就是「只会全开」） |
| 渐变的 5 张里，**底图那条闭嘴线所在的行没被改动** | 缩放支点错了（表现就是「底图的闭嘴一直在」，见上面那条★） |
| 有表情时说话，**嘴那一块和素颜时不一样** | 遮嘴块没生效：`mouthCoverBox` 没框住表情的嘴（换素材后要重测 `MOUTH_COVER_MARGIN`） |

## 八、这个方案的边界

诚实说明它能做到什么、做不到什么：

| 能做到 | 做不到 |
|---|---|
| 张嘴说话（1~3 档嘴型，看你做了几张差分）、随机眨眼 | 立体转头（侧脸、仰头） |
| 呼吸浮动、身体微摆；瞳仁跟随鼠标 | 发丝物理、衣服摆动 |
| 摸头/戳身体的即时反应 | 复杂动作（她自带的动作组） |
| 表情（换整张脸：眉眼+嘴一起变），说话时嘴自动让给口型 | 表情的**连续**过渡（差分之间只能硬切） |
| 姿势（招手之类）：整身替换 + 交叉淡入淡出，脸和头发不动；两帧素材就是真的在挥手 | 复杂动作编排（她自带的动作组那样的一整套动作） |
| 任意画风、任意比例 | 同一张脸上叠加"半笑 + 半怒"这种组合（一张差分就是一个表情） |

要上面那些「做不到」的，才需要走 Live2D 建模（Cubism Editor 自己做，或委托建模师）。
两者的交互层是同一套代码，所以将来升级到 Live2D，界面和手感不用重做。
